Los contenedores están abiertos de par en par y lo que renderiza datos está cerrado. Es coherente, no un descuido: cuando un componente recibe una colección por input, su API es ese array, y un slot competiría con él. La consecuencia práctica es la que importa: puedes envolver, componer y rellenar cuanto quieras, pero en el momento en que necesitas cambiar cómo se pinta una fila, no hay extensión posible.

Los bordes, uno a uno

Ninguno de estos falla con un error claro, que es lo que los hace caros. Se manifiestan como algo que simplemente no ocurre.

Añadir arrastre a ap-list desde fuera

Imposible

ap-list pinta su propio <ul>/<li> sin ningún <ng-content>. Una directiva por elemento — cdkDrag es el caso típico — tiene que ir sobre cada hijo arrastrable, y desde la plantilla padre esos <li> no se alcanzan.

No da error de compilación ni de ejecución: el contenedor queda con cero hijos arrastrables y no pasa nada al arrastrar.

Reconstruir la fila en tu aplicación. Es barato si copias las métricas de su CSS, que está hecho enteramente de tokens.

Sustituir la lista interna de ap-file-drop

Imposible

Mismo caso, y tampoco tiene <ng-content>. Su lista se pinta sola desde el input files, cuyo tipo es exactamente { name, size? }: no hay dónde colgar estado propio por fichero.

Usarlo solo como zona de arrastre. Si no le pasas files, el bloque que pinta la lista nunca entra, y tus filas van debajo. Sus showRemove y remove quedan entonces sin uso: el botón de quitar es tuyo.

Un icono que no está en el set

Silencioso

El set son 52 iconos en una lista explícita dentro de scripts/gen-icons.mjs. Aplomo incrusta solo lo que usa: como el nombre es dinámico, ningún bundler puede hacer tree-shaking, y depender del paquete completo costaría los 2.021 iconos de Lucide.

Un nombre no registrado deja un hueco vacío del tamaño pedido, sin avisar. Se diagnostica como un fallo de maquetación, no como un icono que falta.

registerApIcons() al arrancar la app — es la API pública para esto, y así tu bundler solo carga los iconos que nombras. Ejemplo abajo.

Las clases del sistema no salen del componente

Usa tokens

El paquete no usa ViewEncapsulation.None en ningún sitio, así que .ap-list-row y compañía no existen fuera de su componente. En cuanto reconstruyes una pieza, esto deja de ser trivia.

Los 108 tokens --ap-* sí son globales, y el CSS del sistema está hecho enteramente de ellos. Copias las métricas, no las clases — y la pieza sigue moviéndose con el tema.

AccordionItem.children es un TemplateRef

Matiz

El acordeón sí acepta contenido por panel, pero no como contenido libre: es el equivalente Angular del ReactNode que llevaba el array en la versión React. Le pasas referencias a <ng-template>, no marcado suelto.

Reconstruir una fila sin que se note

Cuando toca reconstruir, la fidelidad no sale de imitar a ojo: sale de leer el CSS del componente original y quedarte con sus tokens. Esta es la anatomía de una fila de ap-list, que es la que más se acaba rehaciendo. 

/* franja de estado de 2px + contenido + meta a la derecha */
display: grid;
grid-template-columns: 2px 1fr auto;
gap: var(--ap-space-3);
padding: var(--ap-space-2) var(--ap-space-3) var(--ap-space-2) 0;
border-bottom: 1px solid var(--ap-border);
transition: background-color var(--ap-dur-micro) var(--ap-ease);

/* el título es UI; el subtítulo, secundario */
font: var(--ap-text-ui-medium);
font: var(--ap-text-small); color: var(--ap-text-secondary);

/* la franja toma el tono del estado */
background: var(--ap-gray-200);  /* neutral */
background: var(--ap-ok); / var(--ap-warn); / var(--ap-error);

Registrar un icono que falta

Necesitas lucide como dependencia de tu aplicación. Al importar por nombre, tu bundler se lleva solo esos trazos. 

// main.ts, antes de bootstrapApplication
import { GripVertical, Rocket } from "lucide";
import { registerApIcons } from "@jviserass/aplomo-angular";

registerApIcons({ "grip-vertical": GripVertical, rocket: Rocket });

Y para diagnosticar un icono que no aparece, el paquete expone la lista viva de nombres registrados en ese momento: apIconNames().
